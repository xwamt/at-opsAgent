# 跑第一条 Playbook：日常巡检

`pb.inspection`（日常巡检）是最适合上手的链路：**全程只读**，按清单逐项检查，不会碰任何生产变更。

## 1. 启动巡检

打开聊天视图，然后任选其一：

- 点击 [选择 Playbook](command:atOpsAgent.pickPlaybook)，在列表里选 **日常巡检**；
- 或在输入框键入 `/playbook`，从浮层中选择。

## 2. 看 Agent 怎么干活

启动后 Agent 会按巡检清单逐项执行：

- 通过 AT Terminal / AT Grafana 等插件做**只读**检查（服务状态、磁盘、关键指标、近期告警……）。
- 每一项的证据都会进入**事件脉络**，结论分三态：**已确认 / 假设 / 待定**。
- 巡检的纪律是「**未检查 ≠ 正常**」：没查到的项会明确标注，不会默认为绿。

首次调用只读工具时可能弹一次审批——勾选「本会话不再询问」即可放行后续只读检查；写 / 执行类操作不受此影响，永远单独审批。

## 3. 查看结果

- 聊天顶部的事件脉络条汇总每一步证据；
- 需要全屏排查时打开 [Ops 看板](command:atOpsAgent.openBoard)，按严重级过滤、按日期分组回看整条时间线。

## 下一步

巡检跑通后，可以试试 `pb.metric-anomaly`（指标异常诊断，同样只读），或在真实事故时使用 `pb.incident`（故障排查，写 / 执行操作全部经过双闸审批）。
