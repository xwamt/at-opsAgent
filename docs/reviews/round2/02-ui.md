### 1.2 仍是「原型感」的残留（本轮要清的账）

2. **流式期间裸渲染 Markdown 源码**：`ChatTranscript.vue` L225-228——`streaming` 时走 `{{ text }}` 纯文本 + 光标，`turn/end` 后才切 `MarkdownBlock`。用户全程看到 `**加粗**`、`# 标题`、表格管道符原样滚出，收尾一瞬间整段重排（高度跳变 + 粘底滚动抖动）。Cline/Claude Code/Codex 都是流式中就渲染。

## 2. 富文本与组件差距

### 2.1 Markdown 渲染链的五个缺口

| # | 缺口 | 现状证据 | 竞品基线 |
|---|---|---|---|
| 1 | **围栏代码无语法高亮** | `MarkdownBlock.vue` 未配置 `highlight` 选项；`.ops-md pre` 只有底色边框 | Cline（rehype-highlight）、OpenCode（TUI 内嵌高亮）、Claude Code 全有 |
| 2 | **代码块无复制按钮、无语言标签** | 全库无 clipboard 调用 | Cline/Claude Code 代码块 hover 出 copy；Codex IDE 同 |
| 3 | **流式不渲染 markdown**（finalize 翻转） | `ChatTranscript.vue` L225-228 | Cline/Claude Code 流式渐进渲染；Codex TUI 用「已提交 cell + 缓存 live tail」保证零闪烁（pager_overlay.rs 的 cache-key 方案） |
| 4 | **消息级操作缺失** | assistant 消息无 copy；`chat/export` 协议已有（`host-protocol.ts` L205）+ `atOpsAgent.exportReport` 命令已注册，但 webview 内无入口 | OpenCode `/export` 导出 markdown 到编辑器；Cline 消息 copy |
| 5 | **每个 MarkdownBlock 实例各建一个 MarkdownIt** | `MarkdownBlock.vue` L12-16 在 setup 内 `new MarkdownIt(...)`——百条消息 = 百个解析器实例 | 模块级单例即可 |

表格、列表、引用、链接样式已达标（markdown-it 默认预设含 GFM 表格，`.ops-md table` 有横滚处理），**不需要**再加插件类扩展（footnote/task-list 对运维场景无收益）。

安全边界值得表扬并需写成红线：`html:false` 使 LLM 输出中的 `<script>` 按文本渲染；`UntrustedQuotes.vue` 的外部引用原文走纯文本 blockquote **绝不进 MarkdownBlock**——这条「不可信内容永不进富文本管线」必须作为验收项固化（P0-1 的测试要求）。

### 2.2 运维载荷（日志 / SQL / PromQL / 指标 / 审批命令）的专项差距

1. **LogViewer 不认 ANSI**：`journalctl -f`、`docker logs`、彩色 CLI 输出普遍带 `\x1b[31m` 转义序列，`LogViewer.vue` 原样渲染成乱码。最低要求剥离（strip），更好是把 SGR 颜色映射到 `--vscode-terminal-ansi*` 变量。
2. **行级整行染色太糙**：`levelOf()` 正则命中 ERROR/WARN 后整行染红/黄（L134-140），长行下大片红色反而降低扫读效率；应只给命中关键词加 `<span>`，行底色最多 tint 5%。日志块也没有复制按钮。
3. **SQL/PromQL 无一等公民待遇**：P0-1 的 highlight.js 方案里 `sql` 是现成语言包；PromQL 没有官方包，用 ~30 行自定义 language definition（函数名/duration 字面量/label matcher）注册即可，不要为它引大依赖。
4. **审批命令块是裸 `<pre>`**：`ApprovalBar.vue` L157 把 `commands.join('\n')` 塞进无高亮无逐条复制的块——这是**全产品风险最高的一段文本**（用户要据此判断是否放行），值得最好的呈现：shell 高亮 + 每条命令行尾 copy + 超 3 行折叠。同时 L91-97 的九要素对缺省值渲染「—」，一张简报常见 5+ 行破折号噪声，空要素应折叠进「未提供（N 项）」。
5. **指标点位靠正则猜**：`EvidenceNote.vue` L44-53 `extractPoints` 从 preview 文本里正则抓数字画火花图——版本号、时间戳都会被当数据点。协议应给 `refs[kind=metric]` 加结构化 `points/from/to` 字段，UI 端 regex 仅作兜底并标注「推断」。

### 2.3 thinking 与 assistant 的分治：判断正确，补一个感知缺口

docs/14 P0-id 修复后 thinking/assistant 分 id，正文不再被吞；CoT 恒不渲染（`visibleUntrustedQuotes` 只放行外部引用警示块）。**这个「比 Claude Code 更严」的决策对运维场景是对的**——CoT 里可能复述不可信的告警原文，展开渲染等于给注入内容二次舞台，不要学 Claude Code 的可展开思考块。
但要补感知：模型长思考时用户只看到「正在巡检…」，无法区分「在想」和「卡死」。学 Claude Code 的「Thought for Xs」**只显示时长不显示内容**：`transcript__inspecting` 行加一个跳动的已思考秒数（数据可从 thinking/delta 到达时间在 webview 本地累计，不需要协议改动）。

### 2.4 组件库完整度对照（docs/05 §3 表 vs 代码）

已实现且超出文档：`SubagentInspector`、`UntrustedQuotes`、notice 卡、toolGroup 聚合、`WelcomeState`、`HistoryOverlay`、usage 水位条、软停/硬停双档。
文档承诺未实现且**建议撤销承诺**：`ThinkingTrace`（安全决策取代）、`SkillPicker`（skills 内部化）、mermaid（见 §4「不做」）。
文档承诺未实现且**仍该做**：代码高亮（§4 P0-1）、`PluginCapabilityList` 的空态引导文案（现健康点簇无「装了 AT 插件才会出现」提示，塞进 Settings Capabilities 空态即可）。

## 3. 竞品可抄的 UI 模式（该学 / 不该抄，均按 ops 语境改写）

### 3.1 Codex TUI —— 学「留痕」与「命令是一等公民」

- **审批决策留痕 cell**：Codex 在 transcript 里落一条 `✔ You approved codex to run <cmd> this time`（history_cell.rs `new_approval_decision_cell`）。我们批准/拒绝后只剩 `pendingApproval = null`，transcript 的 approval 行退化成「已处理」——**审计链断在 UI 层**。应改为：决议后 host 追加一条 system/notice 行「已批准 exec · rollback api-gateway · 10:32 · brief b-17」，拒绝同理。这对 SRE 复盘价值极高，改动小（P1-2）。
- **ExecCell 形态**：命令行头 `$ cmd`、退出码、耗时、输出尾行——我们的 ToolCallCard 有耗时无**退出码/发生时刻**，preview 里命令与输出混在一个 JSON 块。值得把「命令」提为卡片展开区的独立行（mono + copy），输出另起。
- **Esc 永不静默继续**：Codex 审批 overlay 保证 Esc = Cancel 明确决议。我们 ApprovalBar 无键盘路径（Enter/Esc 均无绑定），可加但必须是显式决议，不做默认批准。
- 不抄：终端 shimmer/spinner 动效体系、Ctrl+T 全屏 transcript overlay（侧边栏无此空间）。

### 3.2 Kilo Code —— 学「审批的粒度语言」，不抄它的胆量

- **PermissionDock 三选**：approve once / approve always / deny。ops 改写：write/exec **只保留 once/deny**（永不 always）；对未来若出现「只读工具也要确认」的场景，才引入「本会话内同类只读放行」（映射既有 `atOpsAgent.approval.sessionReadAllowlist` 设置）。
- **状态同步纪律**：Kilo 的 auto-approve 盾牌状态在侧边栏/编辑器 tab/Agent Manager 三处 webview 实时同步。我们的 approval/subagent 状态已由 host 单源下发，保持即可；教训是**任何新增全局开关都必须走 hydrate 单源**，不允许 webview 本地记开关。
- **Sub-Agent Viewer**：已抄到位（SubagentBoard + Inspector），差多子代理时 inspector 的**上一个/下一个切换**（Kilo 是多 tab），P2 补个头部左右箭头即可。
- 不抄：运行时全局 auto-approve 盾牌（对生产主机 exec 是灾难）、per-tool Allow/Ask/Deny 大矩阵设置页（我们的风险由 playbook riskCeiling 与审批闸声明式给出，矩阵反而弱化模型）。

### 3.3 OpenCode TUI —— 学「状态行的克制」与「导出」

- **status line 模板**：`ctx ▓▓▓░ 43% | 15k tok | $0.02` 一行讲完运行成本。我们已有 context 细条（Composer L192-204），缺 **cost** 与 tokens 的常显（现在藏在 hover title）。建议水位条旁加一枚 `43% · $0.02` 的 xs 文本，数据 `UsageView.costUsd` 已在协议里。
- **split-footer 心智**：scrollback 不可变、只有 footer 可变，是流式零闪烁的根源。web 侧对应做法就是 P0-2：已完成的块不再重渲染，只有最后一个流式块在动。
- **/export 导出 markdown**：协议与命令都在，只差 chat 内入口（历史抽屉或 view/title menu 加「导出会话」）。OpenCode 的 footer 遮挡正文事故（issue #39368）反向提醒：我们 dock 区（审批+composer）已是文档流布局而非悬浮，保持。
- 不抄：主题系统/声音提醒/ASCII banner——IDE 内主题跟随 VS Code 即可。

### 3.4 Claude Code —— 学「Focus view」，不学「思考可展开」

- **Focus view**：一键把工具调用/结果折叠成可展开行，只留「你的话 + 模型结论 + todo」。ops 改写为「**结论模式**」：长巡检（几十张工具卡）结束后，一键只看 assistant 正文 + 证据便签 + 审批留痕；实现上就是 renderItems 的一个过滤 getter + view/title 或 tstrip 尾部一个 toggle（P2-1）。它的 todo 常显位对应我们的 playbook 阶段 chips（已有）。
- **Plan 文档化评审**：Claude Code 把 plan 开成文档供行内批注。ops 对应：九要素简报超长时「在编辑器中查看简报」深链（brief 转 markdown 虚拟文档），侧边栏只留摘要——P2 级。
- 不学：thinking 可展开（§2.3 已述）、consumer 化的多 session 分组皮肤。

### 明确「不做」清单（防跑偏）

1. **不引重型图表库**（echarts/chart.js/d3）：canvas 火花图 + 未来结构化 points 足够；看板要画大图就跳 Grafana 深链。
2. **不做 mermaid**：≥1MB 打包、CSP/懒加载复杂度换不来运维价值，从 docs/05 撤销承诺。
3. **不上 shiki**：wasm/grammar 体积对侧边栏 webview 过重，highlight.js core 子集（≈40KB）够用。
4. **不做消费级气泡**：保持「用户右侧井 + Agent 全宽」，禁头像、渐变、彩色装饰底、圆角 >6px。
5. **不做 write/exec 的任何 auto-approve / always-allow**：Kilo 的盾牌不进本产品。
6. **不渲染 CoT**：thinking 恒隐藏是安全边界，只补时长感知。
7. **不引虚拟列表/动画三方库**：现有手写虚拟化与 0.15s 单动画已够，保持零 UI 运行时依赖（vue/pinia/markdown-it/codicons + 即将加入的 highlight.js）。

## 附：验收基线汇总

- 富文本：一段含 shell+SQL+表格+链接的巡检报告，流式全程可读、终稿有高亮、任意代码块一键复制、暗亮双主题不破。

- 安全：不可信引用与 CoT 永不进 markdown/高亮管线（测试用例守护）。
