5. 未知工具怎么渲 — 选一个

list_ssh_servers / get_terminal_context 会做专用视图。其余走通用规则。

1

剥壳 + 专用视图 + 键值回退 推荐

去掉 {ok, result, attemptCount, durationMs}。已知工具用卡片/表格；对象数组自动成表；普通对象成键值；失败才 pretty JSON。页脚保留耗时与尝试次数。

2

统一 JSON 树

所有工具同一套可折叠树。实现快，但 SSH 主机、Jenkins 构建这类运维对象不会比现状清晰多少。

3

只美化 JSON（最小改动）

缩进、语法色、折叠长字段。信息不丢，但仍要人读结构。

6. 数据怎么接到这三行上

这是实现约束，不改协议也能做，但建议把 args 和 result 分开存，避免结束时把命令冲掉。

字段来源
标题 · 主机
args.serverName / label / host；没有则用 result 里的 server
标题 · Purpose
命令首行 # Purpose:；缺失则回退命令意图表（磁盘/内存/…）
第二行 · 命令
去掉 Purpose 注释后的正文；长命令默认可折
第三行 · 终端
result.stdout / 流式 partialResult；ANSI 仍走现有 TerminalViewer
风险徽标
沿用 policy 推断：只读命令显示「只读」，即便工具声明是 exec
折叠规则
默认折叠整卡（标题仍在）。write/exec 运行中自动展开。成功后命令行可按你在第 2 节的选择默认收起。
